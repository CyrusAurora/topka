# Support

Topka has one maintainer today (see `MAINTAINERS.md`), working on it in their own time. This page says what you can
expect, so nobody has to guess.

## What you get

- **Best-effort help in the issue tracker.** Questions, bug reports and feature discussions are
  welcome at the repository's [issues page](https://github.com/CyrusAurora/topka/issues). We
  answer when we can — usually within a few days, but no response time is promised, and a quiet
  week is not a signal that a report was ignored.
- **Fixes in the next release.** A confirmed bug is fixed on `main` and reaches you in the next
  quarterly release, or sooner if it is a security fix.
- **Documentation.** `docs/` is the reference; if it is wrong or missing a step, that is a bug and
  worth an issue.

## What you do not get

- **No SLA, no paid support, no consulting.** There is no commercial tier, no priority queue, and
  no one to call. Please do not plan production-critical work around an assumed response time.
- **No private help by direct message or email.** Public issues keep the answer searchable for the
  next person with the same problem.
- **No guarantee a feature request is built.** Requests are read and considered on their merits.

## Before you open an issue

- Search the existing issues, including closed ones.
- Read the tutorial (`docs/tutorial.en.md`, or `docs/tutorial.md` in Chinese) first if you are setting the project up and it did not work; then include
  the exact command and the full error in your report.
- For anything that looks like a security problem, do **not** open a public issue — follow
  `SECURITY.md`.

## A note on a young project

While the major version is 0, a minor release may change configuration or behaviour. The changelog
says what changed and how to adapt. Pin a version if you need stability beyond that.

If the project ever stops being maintained, that will be said plainly in the README and in the
final release notes — not left to be inferred from silence.
